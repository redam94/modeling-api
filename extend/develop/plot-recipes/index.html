    A plot recipe is a function that turns a fitted model's outputs into a chart: an Altair (Vega-Lite) or Plotly figure, the tables it reads by name, and a caption in plain words. The platform sanitizes the result and draws it in a sandboxed frame. Start from the scaffold:

    mapi plugin init acme --kind recipe

    The scaffold¶

    src/acme/plots.py adds a model output over every group and draws one bar per week:

    """acme.weekly_total: a plot recipe scaffolded by ``mapi plugin init --kind recipe``.

``weekly_total`` adds up a model output (``y_hat`` by default) over every group and draws
one bar per week. A recipe is a function ``(inp, settings) -> Figure`` that returns an
Altair (Vega-Lite) chart, the tables it reads by name and a plain-language caption; the
platform sanitizes the result and shows it in a sandboxed frame. Replace the function with
your chart, update the About card and keep ``mapi plugin test`` (the contract kit) green.
"""

from __future__ import annotations

from typing import Any

import altair as alt
import numpy as np
import pandas as pd
import xarray as xr
from mapi_plots.palette import ESTIMATE
from mapi_plots.recipes import Figure, RecipeDataError, RecipeInput, RecipeSettings, named, recipe
from mapi_spec.about import About
from pydantic import Field

__all__ = ["RECIPES", "WeeklyTotalSettings", "weekly_total"]


class WeeklyTotalSettings(RecipeSettings):
    """The settings form of the recipe (the playground renders it from this schema)."""

    var: str = Field("y_hat", max_length=128, description="The variable to add up")
    group: str = Field("predictions", max_length=128, description="The group that holds it")
    time_dim: str = Field("time", max_length=128, description="The weekly time dim")


def _example() -> tuple[Any, dict[str, Any]]:
    """Synthetic predictions of three stores over twelve weeks (the catalog example)."""
    rng = np.random.default_rng(0)
    time = pd.date_range("2025-01-05", periods=12, freq="W-SUN")
    y_hat = 200.0 + rng.normal(0, 15, (3, 12)) + np.linspace(0, 30, 12)
    ds = xr.Dataset(
        {"y_hat": (("geo", "time"), y_hat)},
        coords={"geo": ["north", "south", "east"], "time": time},
    )
    return xr.DataTree.from_dict({"predictions": ds}), {}


ABOUT = About(
    title="Weekly totals",
    summary_plain="Adds up a value over every store or region and shows one bar per week. "
    "Use it to see the total at a glance.",
    use_when=["You want the total of all groups for each week"],
    avoid_when=["You must compare groups with each other"],
    data_needs=["A model output with a weekly time axis"],
    assumptions=["The values can be added up (sales, spend)"],
    outputs=["One bar per week with the total"],
    difficulty="beginner",
    typical_runtime="instant",
    example="Three stores that each sell about 200 a week give bars of about 600.",
)


@recipe(
    "acme.weekly_total",
    title="Weekly totals",
    settings=WeeklyTotalSettings,
    persona="both",
    summary="The total of a value over every group, one bar per week.",
    tags=["totals", "weekly"],
    about=ABOUT,
    example=_example,
    pack_label="Acme",
)
def weekly_total(inp: RecipeInput, s: WeeklyTotalSettings) -> Figure:
    """One bar per week: ``var`` summed over every other dim."""
    ds = inp.require(s.group)
    if s.var not in ds:
        raise RecipeDataError(f"the group {s.group!r} has no variable {s.var!r}")
    da = ds[s.var]
    if s.time_dim not in da.dims:
        raise RecipeDataError(f"{s.var!r} has no {s.time_dim!r} dim")
    total = da.sum([d for d in da.dims if d != s.time_dim])
    frame = pd.DataFrame(
        {"week": pd.to_datetime(total[s.time_dim].values), "total": total.values.astype(float)}
    )
    chart = (
        alt.Chart(named("totals"))
        .mark_bar(color=ESTIMATE)
        .encode(
            x=alt.X("week:T", title="Week"),
            y=alt.Y("total:Q", title=f"Total {s.var}"),
            tooltip=["week:T", "total:Q"],
        )
        .properties(width=s.width, height=s.height)
    )
    peak = frame.loc[frame["total"].idxmax()]
    caption = (
        f"Each bar is the total {s.var} of one week. The highest week is "
        f"{peak['week']:%d %b %Y} with {peak['total']:,.0f}."
    )
    return Figure(chart=chart, datasets={"totals": frame}, caption=caption)


RECIPES = [weekly_total]
"""The ``mapi.plots`` entry point: every recipe listed here is registered."""

    What each part does:

    • WeeklyTotalSettings is the settings form. The Try it playground in Catalog › Plots renders it from this schema. title, width and height come from RecipeSettings.
    • _example returns synthetic input for the catalog example. The catalog card, the docs and the playground draw it, so a recipe without an example has no picture.
    • named("totals") makes the chart read the table totals by name. The table goes in Figure.datasets; the platform ships it as Arrow, never inside the spec.
    • Colours come from mapi_plots.palette (ESTIMATE, BAND, OBSERVED, ...). The plot sandbox swaps each one for its dark-mode variant. A colour that is not in the palette is a warning in the kit.
    • pack_label names your pack on the catalog card.
    • The recipe has no version= argument, so it is 1.0.0. A spec names it as acme.weekly_total@^1.

    More about recipes, Plotly figures and role-bound templates: Plots, recipes and templates and Plots and the sanitizer.

    The entry point¶

    [project.entry-points."mapi.plots"]
acme = "acme.plots:RECIPES"

    The contract kit¶

    """Contract-kit tests for acme.weekly_total (run them with ``mapi plugin test``).

The kit checks the catalog entry and namespace, the About card, the settings schema (safe,
small, defaults valid, unknown keys refused) and the catalog example: it renders, its
datasets are inline, the sanitizer accepts it unchanged and it has a caption.
"""

from __future__ import annotations

import pytest
from mapi_plots.testing import check_recipe

from acme.plots import RECIPES, weekly_total


def test_the_recipe_is_exported() -> None:
    assert weekly_total in RECIPES
    assert weekly_total.catalog_entry().id == "acme.weekly_total"


def test_settings_change_the_example() -> None:
    spec = weekly_total.example_spec({"title": "Store totals"})
    assert spec is not None and spec.title == "Store totals"


@pytest.mark.mapi_contract
def test_contract_kit() -> None:
    report = check_recipe(weekly_total, raise_on_failure=False)
    assert report.ok, report.summary()

    check_recipe checks the catalog entry and the namespace, the About card, the settings schema (safe, at most 16 KiB, defaults valid, unknown keys refused) and the catalog example: it renders, its datasets are inline, the sanitizer accepts it unchanged and it has a caption.

    Use it¶

    On a model, drawn after every fit:

    outputs:
  plots: [acme.weekly_total@^1]

    In a workflow, with a plot.render node. Once installed, the recipe has a card with its example in Catalog › Plots, and Try it opens the playground. Changes to the title, width and height show at once. Other settings draw the chart again in a run on the server: that takes some seconds (about ten on a local stack), and the app shows that it is working. A second request with the same settings comes from a cache. Analysts can restyle your recipe's data with a chart template.
