    • Where next

    Let's make the platform yours. In this tutorial you'll add your own model, preprocessing step, chart and workflow, twice:

    • Part 1, no code (about 20 minutes). You build each one in the app, on the sample project's data, and share it with your team. Any analyst with the editor role can do this.
    • Part 2, with Python (about 20 minutes). You scaffold a plugin package with all five extension kinds, test it, install it on your own dev stack and use it in the app. This part is for developers.

    You don't need Part 1 for Part 2, or the other way round. Pick the part you need.

    Before you start¶

    • Part 1: an account with the editor role in a project, and the sample project. On Home, find the sample card under Start here and pick Make the sample project. It fits a real marketing-mix model on example data, which takes a minute or two. You can carry on while it runs.
    • Part 2: a source checkout of modeling-api with make install done, a stack from make dev, and the checkout's environment active (source .venv/bin/activate), so that mapi is on your path.

    Part 1: no code¶

    1. A model recipe¶

    You'll build a model that explains weekly revenue with the average price, with its own level for each region. You believe that a higher price never raises revenue, and you'll tell the model so.

    1. Open Make your own in the navigation, then Models › Describe a model.
    2. Pick your data: pick the sample dataset, sample-geo-mmm.
    3. What do you want to explain? Pick revenue_gbp. A few weeks are far off the rest, so pick A number with outliers.
    4. What drives it? Add avg_price. Keep the Standardise transform (it is on by default for a new term). For the prior, keep normal and set sigma to 0.5: watch the little curve get narrower. Set the sign to Only lowers (a negative effect).
    5. Does it differ by group? Add region. Each region gets its own level.
    6. Name it: give it the title "Revenue and price, robust to odd weeks". The name fills itself in (revenue-and-price-robust). Keep the scope at your project.

    7. Read Your model, in words on the right, then switch How to edit to YAML. It looks like this:

      # Part 1 of docs/tutorials/your-first-extensions.md: the model recipe you build in
# Make your own > Models, on the sample project's data. `make docs-test` compiles it.
apiVersion: mapi/v1
kind: ModelRecipe
metadata:
  name: revenue-and-price-robust
  title: "Revenue and price, robust to odd weeks"
  summary: "Revenue goes down when price goes up. A few odd weeks do not pull the fit."
base: declarative
declarative:
  outcome: {var: revenue_gbp, family: student_t}
  terms:
    - var: avg_price
      label: Average price
      transform: [{use: standardize}]
      prior: {dist: normal, sigma: 0.5}
      sign: negative
  groups: [{dim: region}]
plots: [core.posterior_forest, core.fit_vs_actual]

    8. Pick Save model, then Fit now.

    When the fit is done, open its run. The posterior forest shows the effect of price below zero: the sign you set is a promise the model keeps. Your recipe is now in Catalog › Yours under "From your team", and in the Build palette.

    What the platform does with your recipe

    It compiles the recipe to normal spec parts with trusted code: a step that makes one row for each week and region, your transforms, and the built-in model tabular.declarative_glm. This is that code, on the sample's schema:

    from mapi_sdk import default_registry
from mapi_spec.guided import draft_schema
from mapi_spec.library import parse_library_text
from mapi_spec.samples import GEO_MMM_SAMPLE, sample_draft

# the schema of the sample project's dataset, as the app ingests it
draft, _ = sample_draft(GEO_MMM_SAMPLE, project="sample")
sample = draft_schema(draft.mapping, GEO_MMM_SAMPLE.answers.columns)
print(sorted(sample.dims), sorted(sample.vars))

    from mapi_spec.model_recipes import compile_model_recipe

builtins = default_registry().catalog()
recipe = parse_library_text((HERE / "extend_tutorial_recipe.yaml").read_text("utf-8"))
compiled = compile_model_recipe(recipe, builtins, schema=sample)
assert compiled.ok, [(i.pointer, i.message) for i in compiled.issues]
print([s.id for s in compiled.pipeline])  # to long rows, then the transforms of each term

    2. A prep preset with your own step¶

    Next, a column of your own: the total media spend of each week. A formula step makes it, and a prep preset saves it for next time.

    1. Make your own › Prep › Make a prep preset.
    2. Add the step Fill gaps (core.impute). Set the method to constant and the value to 0. Mark its columns as a slot: whoever uses the preset picks the columns.
    3. Add the step New column from a formula (core.formula). Set out to total_spend and expr to sum(spend, 'channel'): the spend of every channel, added up.
    4. Under Try it on a dataset, choose sample-geo-mmm and pick spend for the slot. Nothing runs: the server checks each step and shows the data after it, with the new total_spend.
    5. Name it: give it the title "Fill spend gaps, then total media spend" (the name fills itself in: total-media-spend).
    6. Pick Save preset.
    # Part 1 of docs/tutorials/your-first-extensions.md: a prep preset with a slot and a
# formula step, on the sample project's data. `make docs-test` applies it.
apiVersion: mapi/v1
kind: PrepPreset
metadata:
  name: total-media-spend
  title: "Fill spend gaps, then total media spend"
  summary: "Missing spend becomes 0. Then one column adds up the spend of every channel."
slots:
  spend: {kind: var_list, label: "Spend columns", role: spend}
steps:
  - id: fill
    use: core.impute@^1
    with: {vars: ["$slot:spend"], method: constant, value: 0}
  - id: total
    use: core.formula@^1
    with: {out: total_spend, expr: "sum(spend, 'channel')", role: spend}

    Your preset is in the Build palette under "From your team". Add it to any spec and fill the slot.

    What happens when you use it 
    from mapi_spec.prep_presets import apply_prep_preset

prep = parse_library_text((HERE / "extend_tutorial_prep.yaml").read_text("utf-8"))
spend = ["spend"]  # the value you pick for the slot: the columns to fill
steps, issues = apply_prep_preset(prep, {"spend": spend}, schema=sample, catalog=builtins)
assert issues == [], [(i.pointer, i.message) for i in issues]
print([s.id for s in steps])  # ['p_fill', 'p_total']

    3. A chart template¶

    The fit in step 1 draws core.fit_vs_actual: one line for the prediction and dots for the actual values. Let's give its data a new look, with one small panel for each region.

    1. Open Catalog › Plots, find Predicted vs actual and pick Make a chart template.
    2. Pick the starter Predicted against actual, one panel per group. The preview draws it on example data.
    3. Give it a title and a caption that a reader understands, such as "Dots near the diagonal are good predictions."
    4. Save.

    Now open the run of your fit from step 1. Your chart is under Your charts, drawn on the real data of that fit. Chart templates are for your team: share links and client portals never show them.

    4. A team workflow template¶

    Last, share a workflow. Open Workflows, open a workflow that validates (or start one from a template in the gallery), then pick Save as team template from the editor menu. Give it a title and say what it is for. Your teammates now find it in the gallery under From your team, and Start from this gives each of them their own copy.

    That's Part 1. Everything you made is in Catalog › Yours. A tenant admin can promote any of it, so every project in your organisation can use it.

    Part 2: with Python¶

    5. Scaffold a plugin¶

    In the folder that holds your modeling-api checkout (one level up from it):

    mapi plugin init acme --kind model --kind step --kind recipe --kind node --kind template

    You get a package called acme with one module, one entry point and one contract-kit test for each kind:

    Kind Id File
    Model acme.group_mean src/acme/model.py
    Preprocessing step acme.winsorize src/acme/steps.py
    Plot recipe acme.weekly_total src/acme/plots.py
    Workflow node test.acme_zero_share src/acme/nodes.py
    Workflow template acme_weekly_check src/acme/templates.py

    Each one works as it is, with a filled-in About card. Have a look at them now; the Develop pages explain each file. Later, you replace the example code with yours.

    6. Test and validate¶

    mapi plugin test acme            # the contract kits in acme/tests, with this interpreter

    The contract kits run your extensions the way the platform will. All twelve tests pass.

    mapi plugin validate acme        # load only acme's entry points and run every check
mapi --json plugin validate acme > acme-report.json   # the same report as JSON (for CI)

    validate loads only your package's entry points and checks each one, as the runner's loader will. It ends with:

    catalog: 1 models, 1 steps, 1 plots, 1 workflow nodes, 1 workflow templates
all checks passed

    7. Check it against the platform, before you install¶

    You can already see what the platform will make of your plugin. This code registers it next to the built-ins and checks a spec that uses your step, model and recipe on the sample's data. The package is not installed yet (step 8 does that), so the code first puts its src/ on the path: set SRC = "acme/src", the folder mapi plugin init wrote. (Or run the code with PYTHONPATH=acme/src.)

        import sys

    sys.path.insert(0, SRC)  # SRC = "acme/src": not installed yet (step 8 does that), by path
    from acme.model import MODELS
    from acme.plots import RECIPES
    from acme.steps import STEPS

    registry = default_registry().copy()  # every built-in step, model and recipe
    registry.register([*MODELS, *STEPS, *RECIPES])
    catalog = registry.catalog()  # what `describe` publishes once acme is installed
    print([m.manifest.id for m in catalog.models if m.manifest.id.startswith("acme.")])

    # Part 2 of docs/tutorials/your-first-extensions.md: a spec that uses the acme plugin's
# step, model and plot recipe on the sample project's data. `make docs-test` validates it
# against the catalog with acme registered.
apiVersion: mapi/v1
kind: ModelSpec
metadata: {name: revenue-baseline, project: sample}
data:
  dataset: dataset://sample/sample-geo-mmm@latest
  bind:
    dims: {geo: region, time: week}
    vars: {y: revenue_gbp}
  split: {kind: time_holdout, dim: time, last: 8}
pipeline:
  - {id: cap, use: acme.winsorize@^0.1, with: {vars: [y], upper: 0.99}}
model:
  use: acme.group_mean@^0.1
  settings: {shrinkage: 0.2}
outputs:
  plots: [acme.weekly_total@^1]
evaluate: {metrics: [rmse, mape]}

        from mapi_spec.loader import parse_text
    from mapi_spec.spec import ModelSpec
    from mapi_spec.validate import validate_spec

    spec = ModelSpec.model_validate(
        parse_text((HERE / "extend_tutorial_spec.yaml").read_text("utf-8"))
    )
    result = validate_spec(spec, catalog, sample)  # what `mapi check` and Build's Validate do
    print(result.ok, [i.message for i in result.errors])  # True []

    8. Install it on your dev stack¶

    From the checkout:

    make plugin-dev PLUGIN=../acme

    This installs acme in editable mode and adds its folder to .local/extra-plugins.txt, so the image digest changes. Now stop make dev (Ctrl+C) and start it again. At the start, the runner describes the catalog again, now with acme.

    make plugin-doctor

    The doctor lists your five entry points and says whether anything is wrong. If something did not load, it says why. (Want details? Run your plugin on your stack.)

    9. See it in the app¶

    • Catalog › Yours: "Installed by your team" lists acme.group_mean, acme.winsorize and acme.weekly_total, each with its About card.
    • Catalog › Plots: the Weekly totals card has its example picture. Try it opens the playground: change the title and the chart changes at once. Change var and the chart is drawn again on the server, which takes a few seconds.
    • Build: make a new spec in the sample project, paste the spec from step 7, pick Validate, then Fit. The run page shows the Weekly totals chart with the fit's predictions.
    • Workflows: the editor palette has Share of zeros (test.acme_zero_share) under the test nodes. The gallery has Weekly data check under Installed: pick it to start a workflow.

    10. Mix both paths¶

    Your plugin and the no-code library work together. An analyst can make a team preset over your model, a prep preset with your step, a chart template over your recipe, and a team workflow template with your node, all in Make your own. This is what the platform checks when they do:

        from mapi_spec.library import parse_library_doc
    from mapi_spec.model_recipes import compile_model_recipe

    preset = parse_library_doc(
        {
            "apiVersion": "mapi/v1",
            "kind": "ModelRecipe",
            "metadata": {"name": "store-baseline", "title": "Store baseline"},
            "base": "acme.group_mean@^0.1",  # your model, as a team preset
            "settings": {"shrinkage": 0.2},
            "exposed": ["shrinkage"],
            "plots": ["acme.weekly_total@^1"],  # your recipe, drawn after every fit
        }
    )
    used = compile_model_recipe(preset, catalog, exposed={"shrinkage": 0.5})
    assert used.ok, [(i.pointer, i.message) for i in used.issues]
    print(used.spec_fragment()["model"])
    # {'use': 'acme.group_mean@^0.1', 'settings': {'shrinkage': 0.5}}

        from mapi_spec.prep_presets import apply_prep_preset

    prep = parse_library_doc(
        {
            "apiVersion": "mapi/v1",
            "kind": "PrepPreset",
            "metadata": {"name": "cap-then-log", "title": "Cap outliers, then log"},
            "slots": {"spiky": {"kind": "var_list", "label": "Spiky columns"}},
            "steps": [
                {"id": "cap", "use": "acme.winsorize@^0.1",  # your step
                 "with": {"vars": ["$slot:spiky"], "upper": 0.98}},
                {"id": "log", "use": "core.log1p@^1", "with": {"vars": ["$slot:spiky"]}},
            ],
        }
    )  # fmt: skip
    steps, issues = apply_prep_preset(prep, {"spiky": ["sales"]}, schema=None, catalog=catalog)
    assert issues == [], [(i.pointer, i.message) for i in issues]
    print([(s.id, str(s.use)) for s in steps])
    # [('p_cap', 'acme.winsorize@^0.1'), ('p_log', 'core.log1p@^1')]

        from mapi_plots.chart_templates import apply_chart_template

    weekly_total = registry.plot("acme.weekly_total")
    example = weekly_total.example_spec()  # your recipe's catalog example
    chart = parse_library_doc(
        {
            "apiVersion": "mapi/v1",
            "kind": "ChartTemplate",
            "metadata": {"name": "weekly-total-line", "title": "Weekly totals as a line"},
            "source_recipe": "acme.weekly_total@^1",
            "plot": {
                "data": {"name": "totals"},  # a dataset of the recipe's plot, by name
                "mark": {"type": "line", "point": True},
                "encoding": {
                    "x": {"field": "week", "type": "temporal", "title": "Week"},
                    "y": {"field": "total", "type": "quantitative", "title": "Total"},
                },
            },
            "caption_plain": "The total of every store, week by week.",
        }
    )
    plot, issues = apply_chart_template(chart, example, author="lib_01jaf3q2x8m9v7k5h4g3f2e1d0-r1")
    assert plot is not None, issues
    print(plot.id, [i.message for i in issues])  # lib.weekly-total-line ['added $schema']

        from acme.nodes import ZERO_SHARE
    from acme.templates import WEEKLY_CHECK
    from mapi_spec.library import workflow_template_issues
    from mapi_workflows.kit import check_template
    from mapi_workflows.runtime.nodes import all_node_contracts

    nodes = all_node_contracts([ZERO_SHARE.contract])  # built-ins + your node
    assert check_template(WEEKLY_CHECK, nodes=nodes) == []  # your plugin template

    team = parse_library_doc(  # a team template that uses your node
        {
            "apiVersion": "mapi/v1",
            "kind": "WorkflowTemplate",
            "metadata": {"name": "zero-check", "title": "Too many zeros?"},
            "document": {
                "apiVersion": "mapi/v1",
                "kind": "Workflow",
                "metadata": {"name": "zero-check", "project": "default"},
                "inputs": {"data": {"type": "dataset"}},
                "nodes": [
                    {"id": "zeros", "use": "test.acme_zero_share",
                     "with": {"var": "sales", "threshold": 0.05},
                     "inputs": {"data": "inputs.data"}},
                ],
                "outputs": {"zeros": "zeros.result"},
            },
        }
    )  # fmt: skip
    errors = [i for i in workflow_template_issues(team, nodes=nodes) if i.severity == "error"]
    print(errors)  # []: the node is known, its parameters match its contract

    11. Clean up (optional)¶

    make plugin-undev PLUGIN=../acme

    Then restart make dev. Your library items from Part 1 stay: they are data, not code.
