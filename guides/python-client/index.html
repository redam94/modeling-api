    The Python client v0.2¶

    mapi-client (mapi_client, Apache-2.0) is a typed client for the /v1 HTTP API, built on httpx. Every request and response is a Pydantic model from mapi_spec.api, the same models the server uses, so a typo in a field name fails in your editor, not in production. Errors come back as mapi_spec.errors.MapiError subclasses with the server's stable error code.

    It is the client the mapi CLI, make seed and the end-to-end tests use. This page walks through one script, docs/snippets/client_tour.py, which make e2e runs against a live stack; the outputs shown come from running it (shortened in places).

    uv add mapi-client              # or, for xr.Dataset uploads and xr.DataTree results:
uv add "mapi-client[xarray]"

    In the workspace both are already installed. The examples need a running stack and the demo files: make dev, then uv run python scripts/seed.py --export demo/.

    Connect¶

    from mapi_client import Client

api = Client()  # MAPI_URL / MAPI_API_URL, a profile, or http://127.0.0.1:8000
health = api.ready()
print(api.config.base_url, health.status, health.version)

    http://127.0.0.1:8000 ok 0.4.0

    Client() resolves its settings like the CLI: arguments (Client("http://…", token=…, project=…)), then MAPI_URL (or MAPI_API_URL), MAPI_TOKEN, MAPI_PROJECT and MAPI_PROFILE, then a profile in ~/.config/mapi/config.toml, then http://127.0.0.1:8000. api.config.sources says where each value came from. Use the client as a context manager (with Client() as api:) or call close().

    Upload data¶

    versions = {}
for name in ("eu_media_daily", "fx_daily", "holidays_eu", "eu_media_future"):
    versions[name] = api.datasets.upload(f"demo/{name}.zarr.zip", dataset=name)
    print(versions[name].ref, versions[name].status.value, versions[name].sha256[:19])

    dataset://default/eu_media_daily@v2 ready sha256:0073129ba8ee
dataset://default/fx_daily@v2 ready sha256:7f27db4a2ac4
dataset://default/holidays_eu@v2 ready sha256:11abf028d5f5
dataset://default/eu_media_future@v2 ready sha256:2db88e1af79d

    datasets.upload does the whole dance: it creates the dataset if the name is new, opens an upload session, PUTs the bytes to the signed URL (without sending your API credentials there), starts the sandboxed ingest run with a fresh idempotency key, and waits until the version is ready, raising the ingest's error if it fails. It accepts a path, bytes, or an xr.Dataset (with the xarray extra). CSV and Parquet files need a mapping=IngestMapping(…); zarr zips and netCDF files describe themselves.

    The version carries the schema the ingest run checked:

    schema = versions["eu_media_daily"].data_schema  # the DataSchema the ingest run checked
print({dim: spec.policy.value for dim, spec in schema.dims.items()})
print({var: spec.role.value for var, spec in schema.vars.items()})

    {'date': 'extend', 'market': 'new_levels', 'channel': 'fixed'}
{'spend_local': 'spend', 'revenue_local': 'target'}

    Validate a spec¶

    with open("demo/eu-geo-mmm.yaml", encoding="utf-8") as fh:
    spec_yaml = fh.read()

check = api.specs.validate(spec_yaml)
print("valid" if check.valid else [(i.code, i.pointer) for i in check.issues])
for stage in check.stages:  # the schema after every pipeline step, and where the split is
    if stage.data_schema is not None:
        print(stage.name, sorted(stage.data_schema.dims), "<- split" if stage.split else "")

    Validation is synchronous and static: the server never imports plugin code. It returns every issue at once with a JSON pointer (/pipeline/2/with/over), plus the schema at every stage, here in the dataset's canonical names (geo, time) after binding.

    Fit and follow the run¶

    from mapi_client import RunEnd, RunEventFrame, RunLiveFrame

revision = api.specs.upsert(spec_yaml)  # creates the spec, or adds a revision if it changed
run = api.runs.fit(revision.spec_id, revision.revision)

for item in api.runs.stream_events(run.id):  # SSE; resumes with Last-Event-ID
    match item:
        case RunLiveFrame(name="progress", event=event):  # live only, never replayed
            print("  ", event.payload.get("message"))
        case RunEventFrame(name=name, event=event):  # persisted, with an event id
            p = event.payload  # state, warning, diagnostic, metric, complete, error
            print(name, p.get("code") or p.get("name") or "", p.get("message") or p.get("value"))
        case RunEnd(run=final):  # the stream closes after this frame
            print("end:", final.state.value)

run = api.runs.wait(run.id, raise_on_failure=True)
print(run.state.value, run.output_model_version_id)

    runs.stream_events follows the server-sent event stream and yields four kinds of items:

    Item When Notes
    RunSnapshot First, and after every state change The full Run
    RunEventFrame Persisted events: state, warning, diagnostic, metric, checkpoint, complete, error Has an id; replayed after a reconnect
    RunLiveFrame progress and log Live only, never replayed
    RunEnd Once, when the run is terminal The stream then closes

    A dropped connection is resumed with Last-Event-ID, so no persisted event is lost or repeated. runs.wait polls instead (with backoff) and, with raise_on_failure=True, raises the run's error; runs.logs(run_id) pages through the captured output.

    A ModelVersion also carries the signed manifest, the diagnostics, the capabilities, the lineage and the list of artifacts. Download any of them:

    metrics = api.models.download(model.id, mv.version, "metrics.json")  # bytes, CRC32C-checked
api.models.download(model.id, mv.version, "bundle.zarr.zip", dest="eu-geo-mmm.zarr.zip")

    The API checks the manifest's signature before minting the short-lived signed URL, and the client checks the download against the CRC32C and size the object store computed. mapi_sdk.bundle.Bundle opens the downloaded bundle.zarr.zip in a notebook.

    Score¶

    result = api.models.score(
    model.id,
    mv.version,
    {
        "model": mv.ref,
        "mode": "forecast",
        "horizon": {"dim": "time", "periods": 8},
        "data": "dataset://default/eu_media_future@latest",
        "side_tables": {"fx": "dataset://default/fx_daily@latest"},  # score_policy: supplied
        "output": {"kind": "expected", "summary": ["mean", "hdi_90"]},
    },
)
print(result.run.state.value, [link.name for link in result.outputs])
summary = result.tree["summary"]  # an xr.DataTree (needs the `xarray` extra)
print(result.tree.attrs["output_space"])  # {"y_hat": "weekly", ...}: weekly EUR, inverted
print(summary["y_hat"].sel(stat="mean", market="NL").round(0).values)

    succeeded ['plots.json', 'result.json', 'score.zarr.zip', 'ui/summary.arrow']
{"contributions": "weekly", "y_hat": "weekly"}
[69720. 60339. 61101. 60544. 63529. 64553. 61885. 60652.]

    models.score sends the request with Prefer: wait=60. If the run is not done by then, it repeats the same request with the same idempotency key: the server answers with the one run it already created, so a slow score never turns into two runs. With the xarray extra the result tree is downloaded and checked into result.tree.

    The request is a ScoreRequest as a dict, a YAML string or the Pydantic model. apiVersion and kind are filled in for you.

    Errors¶

    from mapi_spec.errors import MapiError, ModeNotSupported

request = {
    "model": mv.ref,
    "mode": "forecast",
    "horizon": {"dim": "time", "periods": 8},
    "data": "dataset://default/eu_media_future@latest",
}
try:  # the fx side table has `score_policy: supplied`, and this request does not supply it
    api.models.score(model.id, mv.version, request)
except MapiError as err:
    print(err.code, err)  # SIDE_TABLE_COVERAGE, with a JSON pointer: /side_tables/fx

try:  # this model cannot filter (that is for state-space models)
    api.models.score(model.id, mv.version, {**request, "mode": "filter"})
except ModeNotSupported as err:
    print(err.code)  # MODE_NOT_SUPPORTED, raised before any run is created

    SIDE_TABLE_COVERAGE validation failed with 1 error; first at /side_tables/fx: side table 'fx' has score_policy 'supplied' and must be provided for stage 'raw'
MODE_NOT_SUPPORTED

    Every RFC 7807 problem from the server becomes a MapiError (or a subclass such as ModeNotSupported, ValidationFailed, CoordPlanError, QuotaExceeded, IntegrityFailure) with the stable code, the HTTP status, the JSON pointer and the individual issues. Both requests above failed during static checks, before any run was created. Transport failures raise mapi_client.TransportError; responses the client cannot parse raise UnexpectedResponse.

    Idempotent calls (GETs, and POSTs with an idempotency key) are retried on 502, 503, 504 and connection errors, honouring Retry-After (ClientConfig.max_retries, default 2). 429 answers are handled as described in Quotas and rate limits.

    Projects, tokens and usage v0.3¶

    On a multi-tenant API the client needs credentials and a project (Tenancy and authentication). Credentials come from an API token (Client(token=…), MAPI_TOKEN or the profile) or, when none is set, from the sign-in mapi login stored for the profile; the client renews that sign-in by itself and only sends it to the API it was made for. The project comes from Client(project=…), MAPI_PROJECT or the profile (mapi use), and is sent as X-Mapi-Project on project-scoped requests only:

    me = api.me()
for tenant in me.tenants:
    for project in tenant.projects:
        print(f"{project.tenant_id}/{project.project_id}: {project.role.value}")
api.use("acme/growth")  # X-Mapi-Project on every project-scoped request from now on

    Mint a token for a program. The secret is returned exactly once and is kept out of repr:

    created = api.tokens.create(
    "atlas-optimiser",
    ["score:geo-mmm-prod", "models:read"],
    expires_in_days=30,
    rate_limit_per_minute=120,
)
print(created.token.display, created.token.expires_at.date())
secret = created.secret  # the only copy: put it in your secret store now

    Usage reports and runs carry exact costs in integer micro-units of the currency:

    report = api.usage.get(period="month", group_by="resource_class")
print(report.totals.amount_micros / 1e6, report.totals.currency)
for quota in report.quotas:
    print(quota.limit_name.value, f"{quota.fraction_used:.0%}", quota.resets_at)
run = api.runs.get("run_01jaf3q2x8m9v7k5h4g3f2e1d0")
print(run.cost.amount_micros, run.cost.currency, run.cost.estimated)

    api.tenants covers tenants, projects and members; api.admin the operator endpoints (tenants, quotas, kill switches, executors, the audit log). See the reference.

    Quotas and rate limits¶

    A 429 answer carries one of two codes. RATE_LIMITED means the request was refused before the server acted on it, so the client waits (Retry-After, then exponential back-off with a little jitter) and sends it again, whatever the method; it raises RateLimited only after RetryPolicy.rate_limit_retries attempts, or at once when the server asks for a wait longer than max_rate_limit_wait. QUOTA_EXCEEDED is raised at once as QuotaExceeded; retry_after_of(exc) says when the quota window resets (None when only finishing running work frees capacity):

    try:
    api.runs.fit("spc_01jaf3q2x8m9v7k5h4g3f2e1d0", 1)
except QuotaExceeded as exc:
    wait = retry_after_of(exc)  # seconds until the quota window resets (None: no reset)
    print(exc.code.value, exc.detail, wait)

    Tune the behaviour with a RetryPolicy (max_quota_wait lets a short quota window be waited out too):

    patient = Client(
    config=config,
    retry=RetryPolicy(rate_limit_retries=8, max_rate_limit_wait=300, max_quota_wait=0),
)

    Endpoints, webhooks and sharing v0.4¶

    The examples in this section come from docs/snippets/client_integrations.py, which runs offline against a stand-in API. The concepts are in Integrations.

    Promote a model version to an endpoint¶

    endpoint = api.endpoints.promote(
    "geo-mmm-prod",
    "model://growth/eu-geo-mmm@v3",
    expected_revision=3,  # 409 CONFLICT if someone else promoted in between
)
print(endpoint.ref, "->", endpoint.model_ref, endpoint.gate.outcome)

    endpoint://growth/geo-mmm-prod -> model://growth/eu-geo-mmm@v3 allowed

    Promotion goes through the promotion gate: a version whose scorecard warns raises MapiError with code OVERRIDE_REQUIRED until a signed-in project admin repeats the call with override=True, reason="…"; PROMOTION_BLOCKED cannot be overridden. api.endpoints also has list, get, history, rollback(alias, reason, to_revision=…) and delete.

    Score an endpoint into xarray¶

    api.endpoint(alias) returns a RemoteEndpoint: schema() says what to send, validate(ds) checks a payload without running it, and score(ds) sends an xr.Dataset inline (as XrJSON, up to 5 MB) and returns the scored xr.Dataset:

    geo_mmm = api.endpoint("geo-mmm-prod")
schema = geo_mmm.schema()
print(sorted(schema.snapshot.input_schema.vars))

plan = xr.Dataset(
    {"spend_local": (("market", "channel", "date"), np.array([[[1200.0], [5300.0]]]))},
    coords={"market": ["de"], "channel": ["search", "tv"], "date": ["2025-12-30"]},
)
result = geo_mmm.score(plan, wait=60)  # inline XrJSON in, xr.Dataset out
print(result["revenue_local"].sel(stat="mean").values)

    ['revenue_local', 'spend_local']
[[13260.]]

    score returns the summary group (a stat dim: mean, hdi_90_lower, hdi_90_upper, ...); pass group="draws" with output={"draws": 100} for posterior draws along sample, or group="delta/summary" for a counterfactual. Any other EndpointScoreCall field is a keyword: mode="forecast", horizon={"dim": "time", "periods": 8}, scenario=plan_ds, future_covariates="carry_last". Like models.score, it sends Prefer: wait=60 and repeats the call with the same idempotency key until the run is done (timeout= bounds the wait), so a slow score never creates two runs. api.endpoints.score(alias, call) is the lower-level call: it returns a ScoreResult with the run, the output links and the downloaded tree. Inline payloads need the xarray extra; larger data is uploaded as a dataset and sent as data="dataset://growth/plan@v2".

    mapi_client.xrjson.encode(ds) and decode(payload) convert between xr.Dataset and the XrJSON payload (the SDK wire format: dates as ISO strings, NaN as null, size-checked before anything is sent).

    Snippets¶

    python = api.endpoints.snippets("geo-mmm-prod", ["python"]).items[0]
print(python.code.splitlines()[2])

    api.endpoints.snippets(alias, languages) returns the code the Integrations hub shows, in Python, TypeScript, curl, R, Apps Script, Atlas and a notebook cell. The Python snippet is exactly the api.endpoints.score(...) call above, the notebook cell the api.endpoint(alias).score(...) form; both run as generated (the client's tests execute them).

    Webhooks¶

    created = api.webhooks.create(
    "https://hooks.example.com/mapi", ["model.version.ready", "endpoint.promoted"]
)
signing_secret = created.secret  # the only copy: store it with the receiver
print(created.webhook.id, created.webhook.secret_hint)

    The signing secret is returned once (by create and rotate_secret) and kept out of repr. api.webhooks also has list, get, update, delete, deliveries(id, status=…) and replay(id, delivery_id). To check deliveries on the receiving side, see Receiving webhooks.

    Render a plot¶

        render = api.plots.render(
        model_id="mdl_01jaf3c1d2e3f4g5h6j7k8m9n0",
        version=3,
        plot_id="mmm.response_curves",
        format="png",
        width=1200,
    )
    path = api.plots.download_render(render, Path(tmp) / "response_curves.png")

    plots.render takes a PlotSpec, a saved plot (saved_plot_id=) or a model version's plot, waits for the sandboxed render like a score, and download_render fetches the file (CRC32C-checked). plots.save, saved, get_saved and delete_saved manage saved plots; create_embed returns a read-only embed link once (embeds, revoke_embed, and the public embed(token) view). See Sharing plots.

    Sign-up, verification, deletion and export¶

        export = api.tenants.export("acme")
    archive = api.tenants.download_export("acme", export.id, Path(tmp) / "acme-export.zip")

    download_export waits for the export to be ready, downloads it through the storage client (never with your API credentials) to a temporary file and renames it into place once its size matches. api.tenants also has verification, request_deletion(tenant_id, confirm=tenant_id), deletion and cancel_deletion; api.signup(...) and api.verify_email(token) are the public sign-up calls (sent without credentials). Operators have api.admin.signups, review_signup, set_verification and retry_deletion. See Deleting and exporting data.

    Guided mode¶

    api.guided drives Guided mode from code: templates() and template(id), detect_roles(template_id, columns=[…] | dataset="dataset://…"), draft(template_id=…, name=…, dataset=…, answers={…}) (the ingest mapping, the ModelSpec and its YAML; nothing is stored), compile({...}) (the ScoreRequest a what-if, forecast or preset stands for) and preview_priors(business_priors, spec_id=…, revision=…) (a sandboxed translate_priors run, waited for).

    Async¶

    AsyncClient has the same resources and arguments; calls are awaited and lists are iterated with async for:

    import asyncio

from mapi_client import AsyncClient


async def recent_fits(n: int = 3) -> list[str]:
    async with AsyncClient() as aapi:  # same resources and arguments, awaited
        found: list[str] = []
        async for run in aapi.runs.list(kind="fit", limit=n):  # follows next_cursor lazily
            found.append(f"{run.id} {run.state.value}")
            if len(found) == n:
                break
        return found


print(asyncio.run(recent_fits()))
