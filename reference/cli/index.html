    CLI and Python client v0.2¶

    Two Apache-2.0 packages talk to the /v1 HTTP API:

    • mapi-client (mapi_client): a typed Python client, sync and async, built on httpx;
    • mapi-cli (mapi): the command line, built on the client and on the SDK for local runs.

    Both use the Pydantic DTOs from mapi_spec.api for every request and response, and raise mapi_spec.errors.MapiError subclasses rebuilt from RFC 7807 problem documents.

    This page is a compact summary. The guides walk through each with tested examples (command line, Python client), and the CLI reference lists every command's --help, generated from the installed CLI.

    Python client¶

    from mapi_client import Client

with Client() as api:  # MAPI_URL / MAPI_TOKEN / ~/.config/mapi/config.toml / 127.0.0.1:8000
    version = api.datasets.upload("eu_media.zarr.zip", dataset="eu_media_daily")
    rev = api.specs.upsert(open("spec.yaml").read())
    run = api.runs.fit(rev.spec_id, rev.revision)
    for item in api.runs.stream_events(run.id):  # SSE, resumes with Last-Event-ID
        print(item)
    run = api.runs.wait(run.id, raise_on_failure=True)
    result = api.models.score(
        model_id,
        1,
        {
            "model": "model://default/eu-geo-mmm@v1",
            "mode": "forecast",
            "horizon": {"dim": "time", "periods": 8},
        },
    )
    result.tree  # xr.DataTree with the `xarray` extra
    Resource Calls
    projects list, get
    catalog get, models, model, steps, plots, schema
    datasets create, list, get, find, ensure, create_upload, create_version, versions, version, wait_version, upload, artifact, download
    specs validate, create, list, get, find, revise, upsert, revisions, revision, dry_run
    runs create, fit, get, list, wait, stream_events, events, logs, plots, cancel, resume, retry
    models list, get, versions, version, artifact, download, score
    plots list, get, validate
    • AsyncClient has the same resources with await and async for.
    • List calls return lazy paginators that follow next_cursor.
    • Calls that accept an Idempotency-Key get a fresh UUID unless you pass one. Idempotent calls are retried on 429, 502, 503, 504 and connection errors, honouring Retry-After.
    • datasets.upload accepts a path, bytes or an xr.Dataset (with the xarray extra). It creates the dataset if needed, PUTs the file to the signed URL, starts the ingest run and waits for the version to be ready. A dataset that carries its raw schema in the mapi_schema attribute keeps its dim policies and roles.
    • runs.stream_events yields RunSnapshot, RunEventFrame (persisted events, with an id), RunLiveFrame (live progress and log frames, without an id) and finally RunEnd.
    • models.score sends Prefer: wait=N. While the run is still going it repeats the same request with the same Idempotency-Key; the server's idempotent replay returns the finished ScoreCallResult with fresh output links.
    • Signed storage URLs are fetched without the API's Authorization header, and every transfer is checked against the storage-computed CRC32C and size.

    Configuration. Arguments beat MAPI_URL (fallback MAPI_API_URL), MAPI_TOKEN and MAPI_PROFILE, which beat a profile in ~/.config/mapi/config.toml ($MAPI_CONFIG, $XDG_CONFIG_HOME), which beats http://127.0.0.1:8000. A token is never sent over plain HTTP to a non-loopback host. M1 has no authentication; OIDC arrives in M2.

    Command line¶

    mapi new geo-mmm -o spec.yaml --with-data   # template + tiny sample data (needs mapi-conformance)
mapi check spec.yaml --data data.zarr.zip   # full static validation against installed plugins
mapi fit spec.yaml --data data.zarr.zip \
    --side-table fx=fx.zarr.zip --side-table holidays=holidays.zarr.zip   # in-process fit
mapi score request.yaml --bundle bundles/geo-mmm --data future.zarr.zip -o result.zarr.zip

mapi serve                                  # the local stack in one process (see below)
mapi fit spec.yaml --data data.zarr.zip --remote @   # upload, create/revise spec, fit, follow
mapi runs ls --state running | get RUN | logs RUN | watch RUN | cancel RUN | retry RUN
mapi datasets ls | upload file.csv --name sales --mapping mapping.yaml
mapi score request.yaml --remote @ --model MODEL_ID --version 1 -o result.zarr.zip
mapi catalog [models|steps|plots] [--remote @]

mapi plugin init acme-demand && mapi plugin test acme-demand   # scaffold + contract kit
mapi spec upgrade spec.yaml --check
mapi config show
    Template (mapi new) What it is Conformance fixture
    geo-mmm Hierarchical geo MMM (weekly EUR, adstock, saturation) E33
    forecast HSGP trend + seasonality forecast C08
    tabular XGBoost demand with quantile uncertainty xgb_store_demand
    glm Hierarchical GLM, long layout E02
    • --remote @ means "the configured API"; --remote URL overrides it for one command.
    • --json prints one JSON document on stdout (runs watch --json prints one JSON event per line). Errors become {"error": {...}} with exit status 1; usage errors exit 2.
    • Local fit and score run plugins in-process (isolation NONE): use them only with code and data you trust. Server, plugin and log text is printed with ANSI and control sequences and bidi overrides removed.

    mapi serve¶

    mapi serve runs mapi-server dev: database migrations, then the API and the orchestrator (dispatcher, reconciler, finalizer and event pump) in one process. Postgres is the embedded pgserver unless DATABASE_URL is set, and the GCS shim is started in-process when nothing listens at MAPI_GCS_ENDPOINT. Runs execute through the local-process executor with the real mapi-runner. For the web app as well, use make dev (Local development).
