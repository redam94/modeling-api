    mapi_pymc¶

    This package is for PyMC models. You write build(). The package gives engines, diagnostics, new levels and counterfactuals.

    The base class¶

    PyMCModel: authors write build(); the platform fits, predicts and checkpoints (§5).

    .. code-block:: python

    class Radon(PyMCModel[RadonSettings]):
    id = "demo.radon"
    version = "1.0.0"
    Settings = RadonSettings
    schema_template = {...}
    outputs = {"y": {"dims": ["obs"], "units_of": "y"}}
    expected = {"y": "mu"}             # output -> Deterministic holding E[y]

    def build(self, ds, s, ctx):
        with pm.Model(coords=ctx.coords()) as m:
            floor = ctx.data("floor")
            county = ctx.data("county_idx")
            a = ctx.hier_effect("a", "county")
            b = pm.Normal("b", 0, 1)
            mu = pm.Deterministic("mu", a[county] + b * floor, dims="obs")
            pm.Normal("y", mu, pm.HalfNormal("sigma", 1), observed=ctx.observed("y"),
                      dims="obs")
        return m

    fit dispatches to the engine in fit.engine (see :mod:mapi_pymc.engines), adds the opt-in groups (prior/prior_predictive, log_likelihood, a thinned posterior_predictive) and turns r-hat, ESS and divergences into diagnostics.

    score rebuilds the model on the canonicalised score data and runs pm.sample_posterior_predictive(..., predictions=True) against the posterior:

    • output.kind = expected returns the Deterministic named in :attr:PyMCModel.expected (no observation noise; counterfactual deltas on it are exact per draw);
    • output.kind = predictive returns draws of the observed variable through icdf(dist, U) with frozen uniforms U seeded by (seed, name, shape). A counterfactual's scenario and baseline therefore share their noise (common random numbers) and the delta's variance is not inflated. Discrete distributions without a symbolic inverse CDF (Poisson, negative binomial, binomial) sample their parameters and push the same frozen uniforms through a numeric inverse CDF (noise = crn_ppf), so a change in one cell's mean never reshuffles the noise of the others. Only distributions with neither fall back to the seeded sampler stream (seeded_stream), whose draws in unchanged cells can still differ between a scenario and its baseline - prefer kind: expected deltas for those.

    PyMCModel ¶

    Bases: CustomModel[SettingsT]

    Base class for PyMC plugins: implement :meth:build; declare outputs and expected.

    Class attributes beyond :class:~mapi_sdk.models.CustomModel:

    • expected - {output: Deterministic name} for kind=expected predictions;
    • predictive - {output: observed RV name} (default: the output's own name);
    • default_engine - engine when the spec names none (default nutpie, else pymc);
    • fast_score_spec - a :class:~mapi_pymc.frozen.FrozenPredictorSpec enabling :meth:frozen_predictor (the manifest then declares fast_score);
    • prior_overlap_vars - free parameters whose prior draws (prior_overlap_draws, forward sampling only, so cheap) are kept as the prior group when the spec keeps no prior itself, so the sanity scorecard can measure how much the data moved them (M3, plausibility.prior_overlap). Empty (the default) keeps nothing.

    Build context¶

    BuildContext: what a PyMC model's build() uses instead of raw coordinates (plan §5).

    build(ds, settings, ctx) runs twice in a model's life: at fit on the training data, and at score on canonicalised score data (fit levels in fit order, then new levels, padded extend dims). The helpers hide the differences so the same build serves both:

    • :meth:BuildContext.coords - the pm.Model(coords=...) mapping; adds <dim>__fit and <dim>__new when the score data holds unseen levels;
    • :meth:BuildContext.data - pm.Data over the current values (rebuild-and-predict);
    • :meth:BuildContext.observed - the target at fit, a shape-only placeholder at score;
    • :meth:BuildContext.hier_effect - a hierarchical effect over a new_levels dim whose new levels are filled according to the dim's strategy (hyperprior draws them from the fitted hyperprior during prediction, with frozen noise so scenario and baseline agree);
    • :meth:BuildContext.position / :attr:BuildContext.anticipated_coords - stable positions along extend dims, so trends and HSGPs see the same axis at fit and at forecast time.

    BuildContext.tree (M4) is the bound tree dataset for models whose capabilities declare input="tree" (FitContext.tree / ScoreContext.tree), else None.

    align ¶

    The platform canonicalises declared dims; undeclared ones arrive in payload order. Positional models must see them in fit order, and with exactly the fit labels.

    hier_effect ¶

    hier_effect(
    name: str,
    dim: str,
    *,
    mu: Any = None,
    sigma: Any = None,
    centered: bool = False,
    mu_sigma: float = 1.0,
    sigma_scale: float = 1.0,
) -> TensorVariable

    A partially pooled effect over dim: name[dim] ~ Normal(mu, sigma).

    Creates name (dims dim) - non-centred by default via name__offset - plus hyperpriors name__mu ~ Normal(0, mu_sigma) and name__sigma ~ HalfNormal (sigma_scale) unless mu/sigma are given (mu may be a scalar or a vector over the full dim). When the score data holds unseen levels, name__new covers them according to the dim's new-level strategy:

    • hyperprior - mu + sigma * z with z frozen standard-normal noise, i.e. a fresh level drawn from the fitted hyperprior for every posterior draw;
    • pooled - the population mean mu;
    • zero - 0;
    • error - raises UNSEEN_LEVELS.

    Returns the effect over the full current dim (fit levels, then new levels).

    position ¶

    position(dim: str, *, scale: bool = False) -> ndarray

    Positions of the current labels along dim relative to the first fit label.

    Datetimes count periods of the dim's frequency, integers count steps of the fit spacing, categories use the fit order (new levels continue after it). With scale=True positions are divided by the last fit position so the fit range maps onto [0, 1] - identically at fit and at forecast time.

    Engines¶

    Inference engines for :class:~mapi_pymc.PyMCModel (plan §5).

    fit.engine picks one of:

    ============== ========================================================================== nutpie nutpie NUTS (default when installed). Fast, parallel chains. Not bit-for-bit reproducible from a seed. Checkpoints are snapshots (draws so far): nutpie cannot export its adaptation, so a retry samples again from the start. pymc PyMC NUTS with segmented sampling: tune once, then draw in chunks of fit.checkpoint.every_draws. After each chunk a resumable checkpoint holds the draws, every chain's position and the full sampler state; a retry resumes exactly where the last chunk ended. Chains run in this process one after another (models with discrete variables fall back to pm.sample without segments). numpyro PyMC's external NUTS bridges, when the library is installed. No segments. blackjax map pm.find_MAP - one "draw" (chain 1, draw 1). advi mean-field ADVI; fit.tune is the number of optimisation steps (default 10,000) and fit.draws the number of draws from the approximation. pathfinder pymc-extras' Pathfinder when pymc-extras is installed. ============== ==========================================================================

    Every engine reports progress through one callback (fraction, message) where the message names the chain ("chain 2/4: sampling 150/500, 0 divergences").

    Start points. By default every MCMC chain starts at the model's initial point with a random jitter. A plugin whose posterior has a trap near the default start (a mixture whose components all switch off) sets :attr:EnginePlan.initvals (values on the constrained scale, by free variable name, as pm.sample(initvals=...)) and jitter=False with dataclasses.replace(plan, ...): every chain then starts at exactly that point (pymc, nutpie and the external NUTS bridges; map, advi and pathfinder ignore both).

    Fast scoring¶

    FrozenPredictor: one compiled PyTensor function for fast posterior predictions (plan §5).

    Ported from pymc-model-interactivity/frozen_predictor.py to PyMC 6 / PyTensor 3 and ArviZ 1.x (posteriors are xr.DataTree / xr.Dataset). Given a model, posterior samples, response expressions and the pm.Data inputs to vary, it compiles a single function vectorised over posterior samples and scenarios:

    • only the free random variables that are ancestors of the responses are bound, to constant posterior samples (so compilation stays small);
    • observed random variables upstream of a response are replaced by their observed values when they do not depend on the inputs, and by icdf(dist, U) with frozen uniform quantiles U (one per sample) when they do - common random numbers across scenarios;
    • SpecifyShape constraints on dims that only the inputs use are removed, so inputs may change length (dims shared with other model variables stay fixed).

    Inputs may have the data variable's own shape (one scenario) or an extra leading scenario axis. Outputs have shape (sample, [scenario,] *dims) before the optional reducer.

    The plan's FrozenPredictorSpec(response_exprs, input_vars, reducer) is the JSON form a plugin declares when capabilities.fast_score is true.

    Checkpoints¶

    Checkpoints for segmented sampling (plan §5, §8.3).

    A long MCMC fit tunes once and then draws in chunks. After each chunk the engine hands a :class:SamplingCheckpoint to a :class:CheckpointSink; a retried run with the same fit key resumes from the last checkpoint instead of starting again.

    Two kinds of checkpoint exist:

    • resumable (engine pymc): the draws so far, every chain's current position and the full NUTS sampling state (adapted step size, mass matrix, RNG state). Resuming continues the same chains exactly; the result equals an uninterrupted run with the same seed.
    • snapshot (engine nutpie): the draws so far only. nutpie cannot export or restore its adaptation state, so a snapshot feeds a PARTIAL bundle but a retry starts again.

    Nothing here pickles. Sampling states are encoded to JSON by :func:encode_state; arrays travel base64-encoded and dataclasses are rebuilt only from classes defined in an allow-list of PyMC step-method modules (and this package).

    Diagnostics¶

    Convergence diagnostics as scorecard-ready :class:~mapi_spec.capabilities.Diagnostic objects.

    Every check reports something - info when it passes - so the sanity scorecard can list it. Thresholds follow current practice (Vehtari et al. 2021): rank-normalised split r-hat below 1.01 and at least 100 effective draws per chain for bulk and tail ESS.
