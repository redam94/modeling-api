    mapi_runner¶

    This package is the run harness in the sandbox (see Runner). The supervisor modules import only mapi_spec and httpx. The worker modules run the SDK harness and the plugin code.

    Job documents and input/output names¶

    What RunSpec.spec holds for each run kind, and the input/output naming conventions.

    The contract lives in :mod:mapi_spec.jobs (shared with the control plane, which writes the RunSpecs and reads the outputs); this module re-exports it for the runner's own modules.

    Supervisor <-> worker channel¶

    The supervisor <-> worker message channel (a socketpair; plan §8.7).

    Frames are a 4-byte big-endian length followed by one UTF-8 JSON object. Every message is validated against the models below; the worker is untrusted, so anything malformed, oversized or of an unknown type is a SANDBOX_VIOLATION on the supervisor side.

    Supervisor -> worker: exactly one :class:StartMessage (no HMAC key, no output URLs). Worker -> supervisor: state, progress, diagnostic, warning, metric, checkpoint, the tracking messages metrics (batched metric points), params, tags and user_log (structured log lines, stream user), media (v0.14: one file the worker wrote under {scratch}/media/), then exactly one terminal result or error. The supervisor accounts every tracking message against StartMessage.tracking (the run's :class:~mapi_spec.tracking.TrackingLimits).

    Supervisor¶

    The trusted supervisor (plan §8.1, §8.5, §8.7).

    One supervisor runs per execution. It:

    1. reads MAPI_RUN_ID/MAPI_NONCE/MAPI_BOOTSTRAP_URL, fetches the RunSpec bootstrap object and deletes it before anything else happens;
    2. starts the untrusted worker (python -I -u -m mapi_runner.worker) as a child with a scrubbed environment, a socketpair for messages and pipes for stdout/stderr - as uid 10001 with no-new-privs when it runs as root, in dev mode otherwise;
    3. validates every worker message, turns them and the captured output into HMAC-signed events on its own stdout (the only thing ever written there), enforces the log, event, tracking, scratch and output caps, and coalesces progress;
    4. handles SIGTERM and the run deadline (forward to the worker, wait for the checkpoint flush, upload a partial manifest);
    5. uploads the media the worker logs (v0.14: each file under {scratch}/media/ is read safely, hashed and checked by the supervisor, then sent through the run's media POST policy) and emits one media event per item;
    6. uploads outputs with the signed POST policy (streaming, hashing as it goes), writes the signed :class:~mapi_spec.run.OutputManifest with the signed PUT and exits with a :class:~mapi_spec.run.RunnerExit code.

    The supervisor never imports plugin code, the SDK, numpy or xarray.

    Worker isolation¶

    Worker process isolation inside the execution (plan §8.1, §9).

    When the supervisor runs as root (Cloud Run gen2 / docker), the worker is started as uid/gid 10001 with no supplementary groups, PR_SET_NO_NEW_PRIVS and no core dumps, and the supervisor makes itself non-dumpable so the worker cannot ptrace it. Anywhere else (macOS, a developer's non-root shell) the uid split is impossible: the run proceeds in dev mode and the supervisor says so in a warning event. Dev mode is never a security boundary.
