    mapi_plots¶

    This package has a sanitizer and templates that use only JSON. These are in the core install. The package also has recipes and converters. These are in the recipes extra.

    Sanitizer¶

    The JSON-only PlotSpec sanitizer (plan §10.3, step 1).

    This is the control-plane half of plot safety. It depends only on mapi-spec and jsonschema and never imports numpy, pandas, altair or plotly (enforced by import-linter and a subprocess test), so mapi_server can run it on every plot it stores or serves.

    from mapi_plots.sanitize import sanitize_plot result = sanitize_plot(plot_json) # PlotSpec | dict | str | bytes result.plot # the sanitized PlotSpec result.changes # what was rewritten (HTML stripped, ...)

    Anything unsafe raises :class:SanitizeError (a MapiError) whose issues carry the JSON pointer, the :class:SanitizeRule (in context["rule"]) and any user-supplied text in untrusted_text. :func:check_plot returns the same issues without raising (for editors).

    Templates¶

    Role/dim-bound plot templates (plan §10.1).

    A template is an ordinary :class:~mapi_spec.plots.PlotSpec whose bindings say what to plot in schema terms ({x: "dim:time", y: "role:target", facet: "dim:geo"}) instead of naming one bundle's variables. :func:apply_template resolves the bindings against a :class:~mapi_spec.schema.DataSchema and fills the placeholders in the spec, so one user-authored "fan chart of the target over time, faceted by geo" applies to every model of a family. This module is JSON-only (it runs in the control plane).

    Placeholders inside spec:

    • {"$bind": "y"} - replaced by a Vega-Lite field definition {"field": ..., "type": ..., "title": ...}; dropped entirely when the channel is optional and unresolved (so encoding.facet simply disappears for a model without geo);
    • "{{y}}" - the bound name; "{{y.field}}" - the name escaped for Vega-Lite field access (dots); "{{y.type}}" - the Vega-Lite type; "{{y.title}}" - name plus units. Placeholders may be embedded in longer strings (titles, captions).

    Converters¶

    Build :class:~mapi_spec.plots.PlotSpec envelopes from Altair charts and Plotly figures.

    Extra recipes only (needs altair, plotly, numpy, pandas and pyarrow).

    • :func:from_altair moves every inline dataset (Altair's consolidated datasets and any data.values) into named Arrow datasets and rewrites the references to {"name": ...}; named data (alt.Data(name=...)) is filled from datasets=.
    • :func:from_plotly decodes plotly.py 6 typed arrays ({dtype, bdata, shape}) and inline data arrays into named Arrow datasets, one per trace (and array length), and binds them with {"$ref": "<dataset>.<column>"}. String columns get the inline-text rules here (HTML stripped to the Plotly allow-list, script/CSS URLs rejected) because the control-plane sanitizer never decodes Arrow; the plot iframe must still re-strip dataset strings.

    Both run the result through the sanitizer unless sanitize=False. Datasets are base64 Arrow IPC streams (:class:~mapi_spec.plots.InlineArrow); datetimes are stored as UTC millisecond timestamps, which JavaScript reads as numbers.

    Recipes¶

    The standard plot recipe catalog (plan §10.2). Extra recipes only.

    Every recipe is a function (DataTree-like, settings) -> PlotSpec with its data in named Arrow datasets (never URLs), a persona and a plain-language caption. They are generated in the runner from a fitted bundle or a score output, so every plugin gets them for free:

    ============================ ========================================================== core.data_overview series per variable, missingness heatmap, group sizes core.prior_predictive prior predictive densities (+ fan over time) core.convergence R-hat / ESS per parameter, worst-parameter table, trace, rank core.posterior_forest point, 50% and 94% HDI per parameter core.ppc predictive density overlay, PIT histogram, coverage core.ppc_fan fit + forecast fan with the split line core.fit_vs_actual predicted against actual core.residuals_over_time actual minus predicted over time core.decomposition stacked contributions and totals core.model_comparison elpd forest (precomputed LOO table, or WAIC) core.counterfactual scenario vs baseline band + total-change distribution core.decision_distribution scalar decision objective per option core.pair corner plot of a few parameters, divergences highlighted core.ridge one density per level of a dim, ordered by mean core.rank_matrix P(rank = k) per item and pairwise P(i above j) core.calibration PIT-ECDF difference with an envelope, or a reliability diagram core.state_sequence observed series above stacked state probabilities core.roc_pr ROC and precision-recall curves of a binary classifier core.confusion 2 x 2 confusion matrix at a probability threshold core.loss_curve loss of an iterative fit (ADVI) per step, moving average core.loo_pit LOO-PIT calibration and the PSIS Pareto k per observation core.energy marginal energy vs energy transitions, E-BFMI per chain core.prior_posterior prior and posterior densities per parameter, ranked by shift ============================ ==========================================================

    The MMM domain pack lives in :mod:mapi_plots.packs.mmm and the tabular-ML pack (ml.feature_importance) in :mod:mapi_plots.packs.ml, and the scientific-model pack (sci.field_map, sci.vector_field, sci.profile_bands, sci.ensemble; Plotly) in :mod:mapi_plots.packs.sci, with the map, tree and polar recipes in :mod:mapi_plots.packs.sci_maps, the image and spectrum recipes in :mod:mapi_plots.packs.sci_images and sci.point_pattern in :mod:mapi_plots.packs.sci_points, the network pack (net.graph; Plotly) in :mod:mapi_plots.packs.net, and the causal pack (causal.impact, causal.pre_fit, causal.donor_weights, causal.event_study) in :mod:mapi_plots.packs.causal. All are exposed through the mapi.plots entry-point group, so mapi_sdk.registry.default_registry() finds them.
