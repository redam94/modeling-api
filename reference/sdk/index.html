    Python SDK (mapi-sdk)¶

    mapi-sdk is the runtime that actually touches your arrays. It runs inside runner images and in your notebook — never in the API server — and does everything between a spec and a fitted, scoreable model: binding, preprocessing with fitted state, the train/holdout split, the model plugin, coordinate handling at score time, inverse transforms, summaries and bundles.

    uv add mapi-sdk          # or: pip install mapi-sdk

    Fit and score in a notebook¶

    The first-model walkthrough builds this step by step. In short, with spec, data and schema from there:

    from mapi_sdk import fit_spec

bundle = fit_spec(spec, data, registry=registry, raw_schema=schema)
print(bundle.metrics.values)  # holdout metrics, in units sold: {'rmse': ..., 'mape': ..., ...}
print(bundle.metrics.n_holdout)  # 48 cells: 3 stores x 2 skus x 8 weeks

    from mapi_sdk import score_bundle

future_weeks = pd.date_range(weeks[-1] + pd.Timedelta(weeks=1), periods=4, freq="W-SUN")
plan = xr.Dataset(
    {
        "price": (dims, np.full((4, 2, 4), 2.9)),
        "promo": (dims, np.zeros((4, 2, 4))),
    },
    # "west" opens next month: the model has never seen it
    coords={"store": [*stores, "west"], "sku": skus, "week": future_weeks},
)

forecast = score_bundle(
    bundle,
    """
    apiVersion: mapi/v1
    kind: ScoreRequest
    model: endpoint://quickstart/fruit-demand
    mode: forecast
    horizon: {dim: time, periods: 4}
    output: {summary: [median, q10, q90]}
    """,
    plan,
    registry=registry,
)
summary = forecast["summary"].to_dataset()
print(summary["y_hat"].dims)  # ('stat', 'store', 'sku', 'week'), in your names
print(summary["y_hat"].sel(stat="median", store="west").values.round(1))
print(forecast.attrs["representation"])  # quantiles: what this model's uncertainty is
print(forecast.attrs["output_space"])  # {"y_hat": "raw"}: log1p undone, back in units sold
print(forecast.attrs["issues"])  # an info notice: 1 new level of 'store' uses 'pooled'

    import tempfile
from pathlib import Path

from mapi_sdk import Bundle

out = Path(tempfile.mkdtemp()) / "fruit-demand-v1"
manifest = bundle.write(out)
print(sorted(p.name for p in out.iterdir()))
# ['bundle.zarr.zip', 'diagnostics.json', 'evaluation', 'manifest.json', 'metrics.json',
#  'plots.json']  - `evaluation/` is the train-only fit that produced the holdout metrics

again = Bundle.read(out, registry)  # every file's size and hashes are verified here
assert again.bundle_id == bundle.bundle_id

    For a model whose representation is draws, add draws: 50 to output and the tree also has a draws group: 50 joint draws taken from the bundle-wide thinning index.

    score_bundle returns an xr.DataTree. Its root attributes record the representation, the output kind (expected or predictive), the output space of every variable (for example weekly — inverse transforms stop at the last reshape step), retransformation labels for point models, and any warnings. Counterfactual requests add baseline/ and delta/ groups.

    How fitting works¶

    fit.mode: evaluate_then_refit (the default) does this:

    1. Bind dataset names to canonical names and check the data against its schema.
    2. Run the stateless prefix of the pipeline on all data, up to the split stage.
    3. Split, fit the remaining steps and the model on train.
    4. Score the holdout through the normal score path (with context rows from train) and compute evaluate.metrics.
    5. Refit every step and the model on all data, so the context tails and terminal state that forecasts start from are the latest ones. The production bundle links the evaluation bundle in its lineage.

    train_only stops after step 4 and keeps the train fit.

    How scoring works¶

    Phase What happens
    CoordPlan Typed early errors from metadata: UNSEEN_LEVELS, COORD_NOT_ALLOWED, HORIZON_EXCEEDS_FIT (409), MISSING_FUTURE_COVARIATE, NON_CONTIGUOUS_EXTENSION, MODE_NOT_SUPPORTED, ...
    Entry Data enters at inputs_stage (default raw). Steps before it — and their side tables — are skipped.
    Replay Each step's stored state is applied; steps with a look-back (lags) get their stored per-group context rows prepended first, after a contiguity check.
    Canonical coords Model-stage data is reordered to the fit order, padded to the full fit set, and new levels are appended with a <dim>__is_new flag.
    Model plugin.score(...) returns the predictions group in the plugin's representation.
    Back to you Context rows are dropped, requested coords selected, outputs inverted to the output space, aggregated (only if statistically valid), summarised and reverse-bound to your dataset names.

    Representations and summaries¶

    Representation Shape Summaries Aggregation
    draws (chain, draw, …) mean, sd, median, hdi_<p>, eti_<p>, q<p> any (per draw)
    quantiles (quantile, …) median, q<p>, eti_<p> (interpolated, never extrapolated) none
    interval (bound, …) interval, point none
    point (…) mean, point sum/mean, flagged
    moments (moment, …) mean, sd, eti_<p> none

    Asking for something invalid — summing quantiles, draws from a point model — fails with CAPABILITY_UNSUPPORTED instead of returning a misleading number.

    Data on the wire¶

    mapi_sdk.wire reads and writes the platform's formats. Readers treat every payload as hostile.

    • XrJSON (to_xrjson / from_xrjson): the xr.Dataset.to_dict() shape with explicit dtypes, null for missing values and caps on elements, dims and string length. Good for small payloads and curl.
    • zarr zip (write_zarr_zip / read_zarr_zip, write_datatree_zip / read_datatree_zip): single-object zarr v3 archives. Strings are vlen-utf8, datetimes are int64 nanoseconds with explicit units, only zstd/blosc compression is accepted, MultiIndexes are reset and restored. The bytes are deterministic.
    • Rows (stack_rows / unstack_rows): stack dims into rows, drop empty rows, and restore them later from the recorded row mask.
    • Arrow IPC (to_arrow_table, write_arrow_ipc): tidy tables for UI views.

    Pickle is never used, anywhere.

    Data checks in plain language¶

    import numpy as np
import pandas as pd
import xarray as xr
from mapi_sdk import infer_schema, validate_dataset
from mapi_spec import DimPolicy

days = pd.date_range("2026-03-01", periods=28, freq="D")
markets = ["DE", "FR", "UK"]
channels = ["tv", "search"]
rng = np.random.default_rng(0)
media = xr.Dataset(
    {
        "revenue": (("market", "date"), rng.gamma(50.0, 20.0, (3, 28))),
        "spend": (("market", "channel", "date"), rng.gamma(5.0, 100.0, (3, 2, 28))),
    },
    coords={"market": markets, "channel": channels, "date": days},
)

schema = infer_schema(
    media,
    targets=["revenue"],
    policies={"market": "new_levels"},
    units={"revenue": "EUR", "spend": "EUR"},
)
print(schema.dims["date"].policy, schema.dims["date"].freq)  # extend D
print(schema.dims["channel"].policy)  # fixed
print(schema.vars["revenue"].role)  # target

    broken = media.copy(deep=True)
broken["revenue"].loc[{"market": ["FR", "UK"], "date": days[10:12]}] = np.nan

for issue in validate_dataset(schema, broken):
    print(issue.severity, issue.code, "-", issue.message)
# error SCHEMA_INVALID - 2 markets are missing 2 days of revenue in March 2026

    Bundles¶

    A bundle directory holds bundle.zarr.zip (spec, schemas, binding, every step's state and context, the model's ArviZ-named groups, native artifacts, fit coordinates per stage, pinned side tables and the thinning index) plus manifest.json, diagnostics.json, plots.json and metrics.json. The manifest records CRC32C and MD5 (in the form GCS reports) and SHA-256 for every file; Bundle.read verifies them.

    Running work through an executor¶

    InprocExecutor implements the platform's Executor protocol in your own process — handy for notebooks and tests, never for untrusted code:

    import asyncio

from mapi_plugin_tabular.datasets import (
    STORE_DEMAND_SCHEMA,
    STORE_DEMAND_SPEC_YAML,
    store_demand_dataset,
)
from mapi_sdk import InprocExecutor
from mapi_spec.executor import ExecState, RunEventType, RunKind, RunSubmit

history = store_demand_dataset(stores=4, skus=2, weeks=60, seed=1)
recent = history.isel(week=slice(-8, None))  # a window of fitted weeks to re-score

executor = InprocExecutor(
    # dataset refs in specs and requests resolve to in-memory datasets
    resolver={
        "dataset://retail/store_sku_weekly@latest": history,
        "dataset://retail/last_8_weeks@v1": recent,
    },
)
print(executor.caps().isolation.name)  # NONE: your own code, in your own process

    async def main() -> None:
    fit = await executor.submit(
        RunSubmit(
            run_id="fit-001",
            kind=RunKind.FIT,
            payload={
                "spec": STORE_DEMAND_SPEC_YAML,
                "raw_schema": STORE_DEMAND_SCHEMA.model_dump(mode="json"),
            },
        ),
        nonce="nonce-fit-0001",  # resubmitting the same nonce returns the same run
    )
    status = await executor.wait(fit, timeout=300)
    print(status.state)  # succeeded
    for event in executor.events(fit):  # the same event stream a cloud run will produce
        if event.type is RunEventType.PROGRESS:
            print(event.seq, event.payload.get("message"))  # 2 validated the spec and the data

    executor.put_bundle("store-demand@1", executor.result(fit))
    score = await executor.submit(
        RunSubmit(
            run_id="score-001",
            kind=RunKind.SCORE,
            payload={
                "bundle": "store-demand@1",
                "request": {
                    "apiVersion": "mapi/v1",
                    "kind": "ScoreRequest",
                    "model": "endpoint://retail/store-demand-xgb",
                    "mode": "predict",
                    "data": "dataset://retail/last_8_weeks@v1",
                },
            },
        ),
        nonce="nonce-score-0001",
    )
    assert (await executor.wait(score, timeout=300)).state is ExecState.SUCCEEDED
    tree = executor.result(score)  # an xr.DataTree, exactly what score_bundle returns
    print(dict(tree["summary"].to_dataset()["y_hat"].sizes))
    # {'stat': 3, 'store_id': 4, 'sku': 2, 'week': 8}


asyncio.run(main())  # in Jupyter: `await main()`

    See Runs and executors.

    Error codes you may see¶

    Every error is a MapiError with a stable code and, where useful, a JSON pointer. Anything your data or a plugin said is kept in untrusted_text, separate from the message. StepError (USER_CODE_ERROR) wraps failures inside steps, SchemaValidationError (SCHEMA_INVALID) reports data problems, BundleError (INTEGRITY_FAILURE) reports damaged or tampered bundles and RunCancelled (CANCELLED) reports cooperative cancellation.
